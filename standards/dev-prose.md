# 개발 문서 레이어

개발 관련 문서, 코드 주석, 결정 기록, 명세를 쓸 때 공용 레이어에 더해 적용한다.

## 원칙

- 일반적으로 사용하는 어휘만 쓴다.
- 영어로 된 기술 용어를 한국어 순화어로 억지로 바꿔 부르지 않는다.
- 사물 주어에 사람 동사를 붙이지 않는다.
- 그 문장을 사람이 읽기 위한 보고서 혹은 문서에 그대로 쓸 수 있는 수준으로 작성한다.

## 이름 짓기

- 은유로 새로운 이름을 만들지 않는다. 은유로 만든 이름은 뜻이 전달되지 않는다.
- 이름은 실제로 통용되는 용어(헤더, 사이드 패널, 섹션, 프로필)에서 고르고, 맞는 용어가 없으면 완전한 문장으로 풀어 쓴다.
- 용어를 바꿀 때는 단어만 바꾸지 않고 그 문장 전체를 다시 쓴다.
- 위치나 규격을 서술할 때 "자리" 같은 모호한 명사 대신 정확한 명사를 쓴다.

## 명세와 규정

명세와 규정 문서는 읽는 사람마다 다르게 해석할 여지를 남기면 안 되므로, 압축하지 않고 완전한 문장으로 작성한다.

- 주어를 명확하게 쓴다. 문서나 규칙의 이름을 주어로 삼는다.
- 조건이 있으면 조건절을 명시하고 문장을 완결한다.
- 대명사로 얼버무리지 않고 대상을 명칭 그대로 부른다.
- 한 줄에는 하나의 의미만 담고, 설명이 이어지면 한 단계 깊은 목록으로 내려 쓴다.
- 지시문처럼 짧게 압축된 문체를 명세에 쓰지 않는다.

## 교정 사전

아래 왼쪽 표현이 반복적으로 나타나므로 오른쪽 표현으로 바꿔 쓴다.

| 피해야 할 표현 | 바른 표현 |
|---|---|
| 앞머리 | frontmatter, 접두어 |
| 방아쇠 | 트리거 |
| 구르다, 구르는 칸 | 스크롤, 스크롤되는 칸 |
| 걷다, 걷히다 (표시 제거) | 감추다, 표시되지 않다 |
| 흘리다 (텍스트 표시) | 그대로 표시하다 |
| 세우다, 서다 (요소 배치) | 표시하다, 배치하다 |
| 들다 (값 보유) | 담다, 갖다 |
| 되살아나다 | 다시 표시되다 |
| 숨쉬다 (모션) | 커졌다 작아지다 |
| 돌다 (실행) | 실행되다, 동작하다 |
| 열쇠 | 키 |
| 단추 | 버튼 |
| 손잡이 | 진입점, 버튼 |
| 자리 (규격 서술) | 위치, 칸, 상황, 역할 중 정확한 명사 |
| 덩이 (요소 그룹) | 블록, 박스 |

## 금지 목록

- 문자열로 대조하는 금지 목록은 `banned-words.json` 에 있다.
- 목록에는 잘못 걸릴 가능성이 낮은 형태만 담는다. 활용형이 다양한 동사는 위 표로만 관리한다.
