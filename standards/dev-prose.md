# 개발 산문 레이어 — 하네스 문서와 주석과 결정 기록과 명세

하네스 문서와 코드 주석과 결정 기록과 명세 같은 개발 산문에 공용 레이어 위로 겹쳐 적용한다.

## 원칙

- 실사용 개발 어휘를 쓴다. 영어 기술 용어를 한국어 순화어로 바꿔 부르지 않는다.
- 사물 주어에 사람 동사를 붙이지 않는다. 서다, 세우다, 들다, 흘리다, 되살아나다, 숨쉬다 계열이 가장 자주 샌다.
- 판정 질문은 하나다. 그 문장을 코드 리뷰나 이슈에 그대로 쓸 수 있는가.

## 조어 금지

- 은유로 새 이름을 만들지 않는다. 곁 패널이나 머리줄이나 사다리 같은 조어는 뜻 전달 자체가 실패한다.
- 이름은 실사용 상용어(헤더, 사이드 패널, 섹션, 프로필, 타이틀바)에서 고르고, 없으면 완전한 문장으로 푼다.
- 용어를 바꿀 때 낱말만 기계로 치환하고 문장 결을 그대로 두면 교체가 끝나지 않는다. 교체는 그 문장을 다시 쓰는 데까지 간다.
- 뭉개는 명사를 규격 문장에 넣지 않는다. "오른쪽 한 자리다" 가 아니라 무엇의 어느 위치인지 그대로 적는다.

## 명세와 규정은 완전 서술로

짧게 압축하는 것이 미덕이 아닌 유일한 글 종류다. 규정 문서는 읽는 사람이 다르게 해석할 여지를 남기면 안 되므로 문장이 길어진다.

- 주어를 명시한다. 문서나 규칙 자체를 주어로 세운다. "용어 정본은 모든 출력에 사용하는 명칭의 단일 기준이다" 꼴이다.
- 조건절을 명시하고 쉼표로 가른 뒤 완결한다. "서술을 할 때에는, ~한다" 꼴이다.
- 불확실한 대명사를 쓰지 않는다. "여기 없는 이름" 이 아니라 "용어 정본에 존재하지 않는 명칭" 으로 대상을 그대로 부른다.
- 지시문 글 종류의 압축(짧은 문장, 쉼표 없음)을 명세에 옮기면 틀린다.
- 한 줄에는 하나의 의미만 담고, 설명이 이어지면 한 단계 깊은 목록으로 내려 쓴다.

## 교정 사전 (기본값)

| 피해야 할 말 | 바른 말 |
|---|---|
| 앞머리 | frontmatter, 접두어 |
| 방아쇠 | 트리거 |
| 구르다, 구르는 칸 | 스크롤, 스크롤되는 칸 |
| 걷다, 걷히다 (표시 제거) | 감추다, 표시되지 않다 |
| 흘리다 (텍스트 표시) | 그대로 표시하다 |
| 세우다, 서다 (요소 배치) | 표시하다, 배치하다 |
| 들다 (값 보유) | 담다, 갖다 |
| 되살아나다 | 다시 표시되다 |
| 숨쉬다 (모션) | 커졌다 작아지다 |
| 돌다 (실행) | 실행되다, 동작하다 |
| 열쇠 | 키 |
| 단추 | 버튼 |
| 손잡이 | 진입점, 버튼 |
| 자리 (규격 서술) | 위치, 칸, 상황, 역할 중 정확한 명사 |
| 덩이 (요소 그룹) | 블록, 박스 |

## 절대 금지 목록

기계 검사용 금지 목록은 `banned-words.json` 하나다. 에이전트가 산출물을 내보내기 전에 이 목록을 직접 대조한다. 목록에는 오탐이 적은 형태만 담고, 동사 활용처럼 오탐이 많은 항목은 이 문서의 표로만 관리한다.
