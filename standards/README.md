# standards — 글쓰기 기준

에이전트가 한국어를 쓸 때 따르는 기준이 전부 이 폴더에 있다. 사람이 읽을 수 있는 평문이고, 팀에 맞게 고쳐 쓰라고 만든 폴더다.

## 적용 순서

층은 아래에서 위로 쌓인다. 위층이 아래층을 지우지 않고, 충돌하면 더 구체적인 층이 이긴다.

| 순서 | 파일 | 무엇을 정하나 |
|---|---|---|
| 1 | [judgment.md](judgment.md) | 무엇을 쓸지. 왜 쓰는가, 누가 읽는가, 무엇이 빠졌는가 |
| 2 | [korean.md](korean.md) | 문장. 무생물 주어, 이중 피동, 번역투 |
| 3 | [discourse.md](discourse.md) | 글의 구성. 시작과 전개와 호흡과 끝, 제목과 소제목 |
| 4 | [style.md](style.md) | 표현과 표기. 화계, em-dash, 이모지, AI 상투 표현 |
| 5 | [genres.md](genres.md) + [genres/](genres/) | 장르 판정과 장르 팩 7종. 실측 리듬 수치와 화계 분포 |

산문이 아닌 글에는 전용 층을 하나 더 겹친다. 산문 규칙을 그대로 옮기면 틀리는 자리들이다.

| 파일 | 언제 |
|---|---|
| [dev-prose.md](dev-prose.md) | 하네스 문서, 코드 주석, 결정 기록, 명세와 규정 |
| [ui-copy.md](ui-copy.md) | 앱과 웹의 화면 문구. 버튼, 라벨, 빈 상태, 확인 대화상자 |
| [slides.md](slides.md) | 발표 자료. 슬라이드 텍스트와 대본 |

`banned-words.json` 은 사람이 아니라 기계가 읽는다. Claude Code 의 훅이 Write 와 Edit 마다 이 목록을 대조한다. 목록의 표현은 잘 쓴 글 실측에서 전 장르 0회로 확인된 것들이다.

## 층이 서로 부딪히는 세 자리

기준을 읽을 때 가장 헷갈리는 곳이다. 전부 "더 구체적인 층이 이긴다"로 풀린다.

- **소제목.** `discourse.md` 는 소제목이 그 절의 주장을 그대로 말해야 한다고 정한다. 산문의 규칙이다. 슬라이드 제목에 이 규칙을 옮기면 틀린다. 슬라이드 제목은 `slides.md` 가 정하는 압축 명사구이고, 화면 라벨은 `ui-copy.md` 가 정하는 정식 명칭이다.
- **비유.** `style.md` 는 비유와 의인화를 금지한다. 예외가 하나 있다. 발표와 교육 자료에서 개념을 설명할 때는 구체 비유를 쓸 수 있고, 그때도 한 덱 안에서 하나의 비유를 끝까지 민다. `slides.md` 가 갖는다.
- **상투어.** `style.md` 의 금지 목록은 장르가 최종 판정한다. "결론적으로"는 보고서에서 정상이고 회고 글에서 AI 티다. 판정표는 `genres.md` 에 있다.

## 수치의 지위

`genres/` 의 팩에 있는 수치(문장 길이 중앙값, 쉼표 밀도, 화계 분포)는 잘 쓴 글을 측정해 얻은 값이다.

목표로 삼되 문장마다 자로 재지 않는다. 중앙값이 ±5자 안에 들면 맞은 것이고, 두 번 조정해도 안 맞으면 더 손대지 말고 수치를 그대로 보고한다. 손으로 맞추면 매번 반대편으로 넘어간다.

팀 글에 안 맞는다고 느끼면 인상으로 바꾸지 말고, 팀이 잘 썼다고 합의한 글 몇 편을 실제로 세어 보고 바꾼다.
