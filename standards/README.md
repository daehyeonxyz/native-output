# standards — 글쓰기 기준

에이전트가 한국어를 쓸 때 따르는 기준이 전부 이 폴더에 있습니다. 사람이 읽을 수 있는 평문이고, 팀에 맞게 고쳐 쓰라고 만든 폴더입니다.

## 어떻게 겹쳐 쓰이나

층은 아래에서 위로 쌓입니다. 위층이 아래층을 지우지 않고, 충돌하면 더 구체적인 층이 이깁니다.

| 순서 | 파일 | 무엇을 정하나 |
|---|---|---|
| 1 | [judgment.md](judgment.md) | 무엇을 쓸지. 왜 쓰는가, 누가 읽는가, 무엇이 빠졌는가 |
| 2 | [korean.md](korean.md) | 문장. 무생물 주어, 이중 피동, 번역투 |
| 3 | [discourse.md](discourse.md) | 글의 구성. 시작과 전개와 호흡과 끝, 제목과 소제목 |
| 4 | [style.md](style.md) | 표현과 표기. 화계, em-dash, 이모지, AI 상투 표현 |
| 5 | [genres.md](genres.md) | 장르별 구조와 리듬 수치. 상투어의 장르별 판정 |

산문이 아닌 글에는 전용 층을 하나 더 겹칩니다. 산문 규칙을 그대로 옮기면 틀리는 자리들입니다.

| 파일 | 언제 |
|---|---|
| [dev-prose.md](dev-prose.md) | 하네스 문서, 코드 주석, 결정 기록, 명세와 규정 |
| [ui-copy.md](ui-copy.md) | 앱과 웹의 화면 문구. 버튼, 라벨, 빈 상태, 확인 대화상자 |
| [slides.md](slides.md) | 발표 자료. 슬라이드 텍스트와 대본 |

`banned-words.json` 은 사람이 아니라 기계가 읽습니다. 훅이 Write 와 Edit 마다 이 목록을 대조합니다.

## 층이 서로 부딪히는 세 자리

기준을 읽을 때 가장 헷갈리는 곳입니다. 전부 "더 구체적인 층이 이긴다" 로 풀립니다.

**소제목.** `discourse.md` 는 소제목이 그 절의 주장을 그대로 말해야 한다고 정합니다. 산문의 규칙입니다. 슬라이드 제목에 이 규칙을 옮기면 틀립니다. 슬라이드 제목은 `slides.md` 가 정하는 압축 명사구이고, 화면 라벨은 `ui-copy.md` 가 정하는 정식 명칭입니다.

**비유.** `style.md` 는 비유와 의인화를 금지합니다. 예외가 하나 있습니다. 발표와 교육 자료에서 개념을 설명할 때는 구체 비유를 쓸 수 있고, 그때도 한 덱 안에서 하나의 비유를 끝까지 밉니다. `slides.md` 가 갖습니다.

**상투어.** `style.md` 의 금지 목록은 장르가 최종 판정합니다. "결론적으로" 는 보고서에서 정상이고 회고 글에서 AI 티입니다. 판정표는 `genres.md` 에 있습니다.

## 수치에 대하여

`genres.md` 에만 수치가 있습니다. 문장 길이 중앙값과 쉼표 밀도이고, 실제 글을 측정해 얻은 기본값입니다.

목표로 삼되 문장마다 자로 재지 않습니다. 중앙값이 ±5자 안에 들면 맞은 것이고, 두 번 조정해도 안 맞으면 더 손대지 말고 수치를 그대로 보고합니다. 손으로 맞추면 매번 반대편으로 넘어갑니다.

팀 글에 안 맞는다고 느끼면 인상으로 바꾸지 말고, 팀이 잘 썼다고 합의한 글 몇 편을 실제로 세어 보고 바꿉니다.

## 고쳐 쓰는 법

[../guides/customize.md](../guides/customize.md) 에 있습니다. 손댈 자리는 셋입니다. `dev-prose.md` 의 교정 사전(회사 용어집), `style.md` 의 상투어 목록(우리 분야에서 정상인 표현), `banned-words.json`(기계가 막을 목록).
