# standards — 글쓰기 기준

## 개요

- 정의: 에이전트가 한국어를 쓸 때 따르는 기준 문서 모음이다.
  - 사람이 읽을 수 있는 평문이고, 팀에 맞게 고쳐 쓴다.

## 적용 순서

레이어는 겹쳐 적용한다. 아래 순서대로 전부 적용하고, 충돌하면 더 구체적인 레이어를 우선한다.

| 순서 | 파일 | 정하는 것 |
|---|---|---|
| 1 | `judgment.md` | 무엇을 쓸지. 왜 쓰는가, 누가 읽는가, 무엇이 빠졌는가 |
| 2 | `korean.md` | 문장. 무생물 주어, 이중 피동, 번역투 |
| 3 | `discourse.md` | 글의 구성. 시작·전개·호흡·끝, 제목과 소제목 |
| 4 | `style.md` | 표현과 표기. 말투, em-dash, 이모지, AI 상투 표현 |
| 5 | `genres.md` + `genres/` | 글 종류 판정과 종류별 팩 7종. 실측 리듬 수치와 말투 분포 |

- 전용 레이어: 산문 규칙이 그대로 통하지 않는 자리에 하나 더 겹친다.
  - `dev-prose.md`: 개발 문서, 코드 주석, 결정 기록, 명세와 규정.
  - `ui-copy.md`: 앱과 웹의 화면 문구. 버튼, 라벨, 빈 상태, 확인 대화상자.
  - `slides.md`: 발표 자료. 슬라이드 텍스트와 대본.

- `banned-words.json`: 절대 금지 목록이다.
  - 잘 쓴 글 실측에서 전체 글 종류 0회로 확인된 표현들이고, 훅이 Write 와 Edit 마다 대조한다.

## 레이어 사이의 우선순위

- 소제목: `discourse.md` 는 절의 주장을 그대로 말하라고 정한다. 산문의 규칙이다.
  - 슬라이드 제목은 `slides.md` 의 압축 명사구가 이긴다.
  - 화면 라벨은 `ui-copy.md` 의 정식 명칭이 이긴다.

- 비유: `style.md` 는 비유와 의인화를 금지한다.
  - 발표·교육 자료의 개념 설명만 예외다. 그때도 한 덱 안에서 하나의 비유를 끝까지 민다. `slides.md` 가 갖는다.

- 상투어: `style.md` 의 목록은 글 종류가 최종 판정한다.
  - "결론적으로" 는 보고서에서 정상이고 회고 글에서 AI 티다. 판정표는 `genres.md` 에 있다.

## 수치의 지위

- 출처: `genres/` 팩의 수치(문장 길이 중앙값, 쉼표 밀도, 말투 분포)는 잘 쓴 글을 측정한 값이다.

- 사용: 목표로 삼되 문장마다 자로 재지 않는다.
  - 중앙값이 ±5자 안에 들면 맞은 것이다.
  - 두 번 조정해도 안 맞으면 더 손대지 말고 수치를 그대로 보고한다. 손으로 맞추면 매번 반대편으로 넘어간다.

- 변경: 인상으로 바꾸지 않는다.
  - 팀 글에 안 맞으면, 팀이 잘 썼다고 합의한 글 몇 편을 실제로 세어 보고 바꾼다.

## 고쳐 쓰는 법

- `dev-prose.md` 의 교정 사전: 회사 용어집과 제품명 표기를 표에 한 행씩 더한다.
- `genres.md` 의 상투어 판정표: 반려된 표현을 넣고, 우리 분야에서 정상인 표현을 "정상인 글 종류" 열에 올린다.
- `banned-words.json`: 활용이 고정된 형태(명사, 완결형 문구)만 담는다. 어간만 잘라 넣으면 오탐이 난다.
- 원칙: 금지 항목은 실제 반려가 관측될 때만 늘린다. 오탐이 쌓이면 아무도 검사를 켜 두지 않는다.
