# standards — 글쓰기 기준

에이전트가 한국어를 쓸 때 따르는 기준이 전부 이 폴더에 있습니다. 사람이 읽을 수 있는 평문이고, 팀에 맞게 고쳐 쓰라고 만든 폴더입니다.

## 어떻게 겹쳐 쓰이나

층은 아래에서 위로 쌓입니다. 위층이 아래층을 지우지 않고, 충돌하면 더 구체적인 층이 이깁니다.

| 순서 | 파일 | 무엇을 정하나 |
|---|---|---|
| 1 | [judgment.md](judgment.md) | 무엇을 쓸지. 왜 쓰는가, 누가 읽는가, 무엇이 빠졌는가 |
| 2 | [korean.md](korean.md) | 문장. 무생물 주어, 이중 피동, 번역투 |
| 3 | [discourse.md](discourse.md) | 글의 구성. 시작과 전개와 호흡과 끝 |
| 4 | [style.md](style.md) | 표현과 표기. 화계, em-dash, 이모지, AI 상투 표현 |
| 5 | [genres.md](genres.md) | 장르별 구조. 블로그, 에세이, 보고서, 필기, 단문, 지시문 |

산문이 아닌 글에는 전용 층을 하나 더 겹칩니다. 산문 규칙을 그대로 옮기면 틀리는 자리들입니다.

| 파일 | 언제 |
|---|---|
| [dev-prose.md](dev-prose.md) | 하네스 문서, 코드 주석, 결정 기록, 명세와 규정 |
| [ui-copy.md](ui-copy.md) | 앱과 웹의 화면 문구. 버튼, 라벨, 빈 상태, 확인 대화상자 |
| [slides.md](slides.md) | 발표 자료. 슬라이드 텍스트와 대본 |

`banned-words.json` 은 사람이 아니라 기계가 읽습니다. 훅이 Write 와 Edit 마다 이 목록을 대조합니다.

## 팀 표준으로 고쳐 쓰기

이 폴더는 고쳐 쓰라고 있습니다. 실제로 손댈 자리는 셋입니다.

1. **`style.md` 의 AI 상투 표현 목록.** 팀에서 실제로 반려된 표현을 넣고, 우리 분야에서 정상인 표현은 뺍니다.
2. **`dev-prose.md` 의 교정 사전.** 회사 용어집이 있으면 여기로 옮깁니다. 제품명과 사내 용어의 표기를 고정하는 자리입니다.
3. **`banned-words.json`.** 기계가 막을 항목만 담습니다. 오탐이 적은 형태(활용하지 않는 명사)만 넣고, 동사처럼 활용이 갈리는 말은 `dev-prose.md` 의 표로만 관리합니다.

고칠 때 지킬 것이 하나 있습니다. **금지 항목은 실제 반려가 관측될 때만 늘립니다.** 있을 법한 표현을 미리 넣으면 오탐이 쌓이고, 오탐이 쌓이면 아무도 이 문을 열어 두지 않습니다.

## 수치를 넣지 않는 이유

이 폴더의 어느 파일에도 문장 길이나 쉼표 밀도 같은 수치가 없습니다. 그런 수치는 실제 글을 측정해야 나오고, 측정 없이 적어 넣은 수치는 근거가 없습니다. 본인 글로 수치를 만드는 절차는 [../guides/personalize.md](../guides/personalize.md) 에 있고, 결과는 `personal/` 로 들어갑니다.
