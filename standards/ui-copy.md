# 화면 문구 층 — 앱과 웹의 UI 텍스트

버튼과 라벨과 빈 상태와 확인 대화상자처럼 화면에 인쇄되는 짧은 문구에 공용 층 위로 겹쳐 적용한다. 산문 규칙이 그대로 통하지 않는 자리다. 라벨은 문장이 아니라 이름이고, 화면은 문장 없이도 행동으로 뜻을 전하기 때문이다.

## 라벨은 이름이다

- 서술어 명사화 꼴을 이름으로 쓰지 않는다. "이은 것" 이 아니라 "연결" 이고, "쌓인 것 보기" 가 아니라 그 화면의 정식 명칭이다.
- 정식 한자어나 실사용 명칭을 쓴다. 산문의 규칙(명사화 절제, 무생물 주어 금지)이 라벨에는 더 세게 적용된다. 라벨에는 풀어 쓸 자리가 없어서 명사화 꼴이 이름 구실을 못 한다.
- 은유로 새 이름을 만들지 않는다. 이름은 그 분야의 실사용 상용어에서 고르고, 없으면 완전한 문장으로 푼다.

## 문구보다 흐름이 먼저다

- 안심 문구와 보증 문구는 최후 수단이다. 그렇게 느끼도록 흐름 안에서 보이게 만드는 것이 먼저다.
- 판정 질문은 하나다. **이 사실을 사용자가 지금 이 화면에서 눈으로 보는가.** 보면 쓰지 않고, 못 보면 쓴다.
- 못 보는 순간은 셋이다. 실패한 순간과 파괴적으로 보이는 확인과 아직 벌어지지 않은 일이다. 앱이 무엇을 하지 않는다는 약속도 여기 든다. 없는 일은 화면에 안 보이니 문장 말고는 전할 길이 없다.
- 첫 실행 화면은 예외가 아니라 반대다. 처음 여는 화면에서는 밀도가 안심보다 앞선다. 겪어 봐야 믿게 되는 약속은 한 번도 써 보지 않은 사람 앞에서 설교로 읽힌다.

## 옮기기는 접기가 아니다

- 반려된 문구를 다른 자리로 옮기면 같은 설교가 자리만 바꾼 것이다. 반려의 원인이 자리였는지 존재였는지를 먼저 가른다.
- 의미 없는 상태 문구와 메타 문구(개수 나열 포함)는 다듬을 대상이 아니라 지울 대상이다. 문구를 판정하기 전에 그 자리가 있어야 하는지부터 의심한다.
- 눌렀을 때 화면이 그 자리에서 바뀌는 항목에 결과를 앞질러 말하는 설명 줄을 달지 않는다.

## 화계는 세어서 정한다

- 화면 문구는 산문이 아니라서 산문의 화계 기준이 그대로 오지 않는다. 화계를 인상으로 단정하지 않는다.
- 화면이 사용자에게 직접 말하는 층은 발표 대본과 같은 성질이다. 청중에게 직접 말하는 자리이므로 경어체가 기본이다.
- 기존 제품의 문구를 참고하라는 지시가 오면 읽고 인상을 말하지 않고 센다. 문자열을 전부 뽑아 화계별로 세고, 그 수치를 근거로 통일한다.

```bash
grep -rhoE '"[^"]*[가-힣][^"]*"' src --include="*.tsx" --include="*.ts" | sed 's/^"//; s/"$//' | sort -u
```

- 한 컴포넌트 안에서 화계가 갈리는 것이 가장 흔한 결함이다. "없어요" 와 "없습니다" 가 같은 빈 상태에 함께 살면 둘 중 하나로 맞춘다.
- 라벨 후보를 상상하지 않고 제품이 이미 쓰는 말에서 고른다. 다만 그 말이 제품 어휘에 있다는 것과 이 개념에 맞는다는 것은 다른 판정이다. 둘을 섞지 않는다.
