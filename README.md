# native-output

AI가 쓰는 한국어를 잘 쓴 글로 만드는 Claude 스킬. Claude 앱(chat)과 Claude Code 어디서나 쓴다.

## 무엇을 해결하나

AI에게 글을 맡기면 매끈해 보이지만 어딘가 어색하다. 영어를 그대로 옮긴 듯한 문장 구조, 결론을 뒤로 미루는 구성, 어느 글에나 나오는 표현이 섞이면서 읽는 사람이 AI가 쓴 글임을 바로 알아챈다.

native-output은 그 기준을 명시된 문서로 만들어 에이전트가 매번 따르게 한다. 설치하고 나면 따로 부르지 않아도 한국어가 들어가는 모든 산출물에 적용된다. 문서와 보고서, 커밋 메시지, 코드 주석, 화면 문구, 발표 자료까지 전부다.

목표는 "사람이 쓴 것처럼"이 아니라 **잘 쓴 글**이다. AI 티가 사라지는 것은 그 결과다.

## 다른 접근과 무엇이 다른가

- **장르가 판정한다.** 흔한 방식은 AI 상투어 목록을 만들어 일괄 제거하는 것인데, 그러면 멀쩡한 글이 망가진다. "결론적으로"는 보고서에서 정당한 어휘이고 회고 글에서 AI 티다. "먼저, 둘째, 셋째"는 발표 자료의 정상 장치다. 이 스킬은 장르별로 무엇이 정상인지를 실측 표로 갖는다.
- **수치가 실측이다.** 장르별 문장 길이 중앙값(캐주얼 단문 26.5자 ~ 보고서 80자), 쉼표 밀도, 화계 분포가 잘 쓴 글을 측정한 값으로 들어 있다. 산문에서는 쉼표를 정상적으로 쓰고, 쉼표를 아끼는 것은 단문과 슬라이드의 특징이다.
- **산문 규칙을 산문이 아닌 곳에 옮기지 않는다.** 소제목은 그 절의 주장을 그대로 말해야 하지만, 슬라이드 제목에 같은 규칙을 적용하면 틀린다. 슬라이드 제목은 "AI가 답변을 생성하는 방식"이 아니라 "AI의 동작 원리"다. 화면 라벨은 문장이 아니라 이름이라 더 강한 규칙을 받는다.

## 설치

### Claude 앱 (chat) — 주 사용처

1. 이 폴더를 zip 으로 묶는다 (배포받은 zip 그대로면 된다).
2. claude.ai 설정 → 기능(Capabilities) → 스킬에서 zip 을 올린다.
3. 끝. 한국어 글을 쓰는 대화에서 자동으로 적용된다.

### Claude Code

1. 이 폴더를 통째로 `~/.claude/skills/native-output/` 에 둔다. 폴더 이름은 `native-output` 그대로여야 한다.
2. Claude Code 에서 `/native-output setup` 이라고 입력한다.
3. 검사 강도를 물어보면 **차단(`block`)** 을 고른다. 알림만(`warn`)은 에이전트가 무시할 수 있어서, 기준이 실제로 강제되는 것은 차단뿐이다.
4. Claude Code 를 한 번 재시작한다.

node 만 있으면 된다. 시스템에 남는 것은 `~/.claude/settings.json` 의 훅 세 줄과 `~/.claude/rules/` 의 규칙 파일 하나뿐이다. 자세한 절차와 문제 해결은 [guides/setup.md](guides/setup.md).

## 설치한 다음

할 일이 없다. 한국어 글을 쓰는 작업이면 자동으로 적용된다.

- 특별히 강조하고 싶으면 "자연스럽게 써 줘", "AI 티 빼줘" 라고 말한다.
- Claude Code 에서 남의 글이나 기계 생성물을 다룰 때는 `NATIVE_OUTPUT_GATE=off` 를 붙여 검사를 끈다.

## 폴더 구조

폴더마다 역할이 하나씩이다.

```text
native-output/
  README.md      ← 지금 읽는 문서
  SKILL.md         에이전트가 매번 따르는 작업 지침
  standards/       글쓰기 기준. 팀에 맞게 고쳐 쓰는 곳
    genres/        장르 팩 7종 (실측 수치 포함)
  guides/          사람이 필요할 때 여는 절차 문서
  install/         Claude Code 전용 (훅, 설치 스크립트, 전역 규칙)
```

| 폴더 | 무엇이 들었나 |
|---|---|
| [standards/](standards/) | 판단·문장·글·표현·장르의 다섯 층, 개발 산문·화면 문구·발표 자료의 전용 층, 장르 팩 7종 |
| [guides/](guides/) | [설치](guides/setup.md), [팀 기준으로 고치기](guides/customize.md), [독립 검수 절차](guides/review.md) |
| install/ | 훅 3종, 설치 스크립트 2종, 전역 규칙. Claude Code 의 setup 이 알아서 쓴다 |

층이 왜 이 순서로 겹치는지는 [standards/README.md](standards/README.md) 에 있다.

## 팀 기준으로 쓰기

`standards/` 를 회사 글쓰기 기준으로 고쳐 두고 그 폴더를 나눠 주면, 팀원 모두의 에이전트가 같은 기준으로 쓴다. 손댈 자리는 셋이다. 회사 용어집, 우리 분야에서 정상인 표현, 기계가 막을 목록. 상세는 [guides/customize.md](guides/customize.md).

고칠 때 지킬 것이 하나 있다. **금지 항목은 실제 반려가 관측될 때만 늘린다.** 기준을 죽이는 것은 느슨함이 아니라 오탐이다.

## 이 스킬이 하지 않는 것

- **특정인의 문체를 흉내 내지 않는다.** 목적은 잘 쓴 글이지 누군가처럼 쓰는 것이 아니다.
- **기계로 일괄 치환하지 않는다.** 금지 목록에 걸렸는지가 아니라 그 문장이 자연스러운 한국어인지가 최종 판정이다.
- **없는 수치를 만들지 않는다.** 수치는 전부 실측이고, 목록에 없는 장르는 가장 가까운 장르로 대용한 뒤 그 사실을 밝힌다.
