# native-output

AI가 쓰는 한국어를 잘 쓴 글로 만드는 Claude Code 스킬.

## 무엇을 해결하나

AI에게 글을 맡기면 매끈해 보이지만 어딘가 어색합니다. 영어를 그대로 옮긴 듯한 문장 구조, 결론을 뒤로 미루는 구성, 어느 글에나 나오는 표현이 섞이면서 읽는 사람이 AI가 쓴 글임을 바로 알아챕니다.

native-output은 그 기준을 명시된 문서로 만들어 에이전트가 매번 따르게 합니다. 설치하고 나면 **따로 부르지 않아도** 한국어가 들어가는 모든 산출물에 적용됩니다. 문서와 보고서, 커밋 메시지, 코드 주석, 화면 문구, 발표 자료까지 전부입니다.

목표는 "사람이 쓴 것처럼" 이 아니라 **잘 쓴 글**입니다. AI 티가 사라지는 것은 그 결과입니다.

## 다른 접근과 무엇이 다른가

**장르가 판정합니다.** 흔한 방식은 AI 상투어 목록을 만들어 일괄 제거하는 것인데, 그러면 멀쩡한 글이 망가집니다. "결론적으로" 는 보고서에서 정당한 어휘이고 회고 글에서 AI 티입니다. "먼저, 둘째, 셋째" 는 발표 자료의 정상 장치입니다. 이 스킬은 장르별로 무엇이 정상인지를 표로 갖고 있습니다.

**리듬이 장르마다 다릅니다.** 문장 길이 중앙값이 캐주얼 단문은 26자, 보고서는 80자입니다. 산문에서는 쉼표를 정상적으로 쓰고, 쉼표를 아끼는 것은 단문과 슬라이드의 특징입니다. 하나의 "좋은 문장" 기준을 모든 글에 적용하면 어느 한쪽이 반드시 망가집니다.

**산문 규칙을 산문이 아닌 곳에 옮기지 않습니다.** 소제목은 그 절의 주장을 그대로 말해야 하지만, 슬라이드 제목에 같은 규칙을 적용하면 틀립니다. 슬라이드 제목은 "AI가 답변을 생성하는 방식" 이 아니라 "AI의 동작 원리" 입니다. 화면 라벨은 문장이 아니라 이름이라 더 강한 규칙을 받습니다.

## 빠른 시작

1. 이 폴더를 통째로 `~/.claude/skills/native-output/` 에 둡니다. 폴더 이름은 `native-output` 그대로여야 합니다.
2. Claude Code에서 `/native-output setup` 이라고 입력합니다.
3. 검사 강도를 물어보면 처음이라면 **알림만(`warn`)** 을 고릅니다.
4. Claude Code를 한 번 재시작합니다.

node만 있으면 됩니다. 설치되는 것은 `~/.claude/settings.json` 의 훅 세 줄과 `~/.claude/rules/` 의 규칙 파일 하나뿐입니다. 자세한 절차와 문제 해결은 [guides/setup.md](guides/setup.md) 에 있습니다.

## 설치한 다음

할 일이 없습니다. 한국어 글을 쓰는 작업이면 자동으로 적용됩니다.

- 특별히 강조하고 싶으면 "자연스럽게 써 줘", "AI 티 빼줘" 라고 말합니다.
- 남의 글이나 기계가 만든 글을 다룰 때는 `NATIVE_OUTPUT_GATE=off` 를 붙여 실행해 검사를 끕니다.

## 폴더 구조

폴더마다 역할이 하나씩입니다.

```text
native-output/
  README.md      ← 지금 읽는 문서
  SKILL.md         에이전트가 매번 따르는 작업 지침
  standards/       글쓰기 기준. 팀에 맞게 고쳐 쓰는 곳
  guides/          사람이 필요할 때 여는 절차 문서
  install/         설치되는 것들 (훅, 설치 스크립트, 전역 규칙)
```

| 폴더 | 무엇이 들었나 |
|---|---|
| [standards/](standards/) | 판단·문장·글·표현·장르의 다섯 층과, 개발 산문·화면 문구·발표 자료의 전용 층 |
| [guides/](guides/) | [설치](guides/setup.md), [팀 기준으로 고치기](guides/customize.md), [독립 검수 절차](guides/review.md) |
| install/ | 훅 3종, 설치 스크립트 2종, 전역 규칙 파일. setup이 알아서 씁니다 |

층이 왜 이 순서로 겹치는지는 [standards/README.md](standards/README.md) 에 있습니다.

## 팀 기준으로 쓰기

`standards/` 를 회사 글쓰기 기준으로 고쳐 두고 그 폴더를 나눠 주면, 팀원 모두의 에이전트가 같은 기준으로 씁니다. 용어 표기와 금지 표현을 한곳에서 관리하는 셈입니다.

손댈 자리는 셋입니다. 회사 용어집, 우리 분야에서 정상인 표현, 기계가 막을 목록. 자세한 것은 [guides/customize.md](guides/customize.md) 에 있습니다.

고칠 때 지킬 것이 하나 있습니다. **금지 항목은 실제 반려가 관측될 때만 늘립니다.** 기준을 죽이는 것은 느슨함이 아니라 오탐입니다.

## 이 스킬이 하지 않는 것

- **특정인의 문체를 흉내 내지 않습니다.** 목적은 잘 쓴 글이지 누군가처럼 쓰는 것이 아닙니다.
- **기계로 일괄 치환하지 않습니다.** 금지 목록에 걸렸는지가 아니라 그 문장이 자연스러운 한국어인지가 최종 판정입니다.
- **없는 수치를 만들지 않습니다.** 장르 기준의 수치는 실제 글을 측정한 값이고, 목록에 없는 장르는 가장 가까운 장르로 대용한 뒤 그 사실을 밝힙니다.
