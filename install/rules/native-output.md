# 한국어 출력 규칙

에이전트가 쓰는 모든 한국어에 적용하는 전역 규칙이다. 세션마다 자동으로 로드되고 항상 적용한다. 세부 기준은 native-output 스킬의 `standards/` 가 갖는다.

## 적용 범위

한국어가 포함된 산출물 전부다. 문서, 보고서, 커밋 메시지, PR 설명, 코드 주석, 화면 문구, 발표 자료, 사용자에게 보내는 대화 응답이 해당한다. 사용자가 스킬을 부르지 않아도 적용한다.

## 쓰기 전

- 한국어 산출물을 쓰는 작업이면 먼저 Skill 도구로 native-output 을 부르고, 그 글의 종류에 해당하는 `standards/` 문서를 읽는다. 사용자가 시키지 않아도 부른다.
- 목적과 독자를 먼저 정한다. 왜 쓰는가, 어디에 실리고 누가 읽는가, 무엇을 전달하는가, 어떤 내용이 필요한가, 어떤 형식으로 쓰는가의 순서로 답한다. 말투는 이 답의 결과로 정한다.
- 기존 글을 고칠 때는 내용이 목적에 맞는지 먼저 판단한다.

## 쓸 때

- 문장: 무생물 주어를 행위자로 만들지 않는다. "~을 갖는다" 와 이중 피동과 "~를 통해" 를 쓰지 않는다.
- 구성: 결론이나 판단을 먼저 쓰고 근거를 뒤에 쓴다. 반론은 해당 주장 옆에서 다룬다. 개수를 예고했으면 바로 전부 나열한다.
- 표현: 한 글 안에서 존댓말과 반말을 섞지 않는다. em-dash 와 이모지를 쓰지 않는다. 비유와 의인화를 쓰지 않는다.
- 글 종류: 문장 길이와 쉼표는 글 종류마다 다르다. `standards/genres.md` 의 표를 기준으로 삼는다. 산문에서는 쉼표를 정상적으로 쓴다.
- 제목: 산문의 소제목은 그 절의 주장을 요약한다. 슬라이드 제목과 화면 라벨은 반대로 짧은 명사구와 명칭으로 쓴다.

## 판단

- 최종 판단은 그 문장이 자연스러운 한국어인가로 한다. 금지 목록에 걸렸는가가 아니다.
- 상투 표현은 글 종류가 판정한다. "결론적으로" 는 보고서에서 정상이고 회고 글에서는 AI 상투 표현이다.
- 교정은 원문을 읽고 문장 단위로 다시 쓴다. 일괄 치환하지 않는다.
- 수치를 지어내지 않는다. 기준에 없는 글 종류는 가장 가까운 종류로 대신하고 그 사실을 밝힌다.
- 기준에 없는 글 종류의 말투는 단정하지 않고 후보와 근거를 정리해 사용자에게 묻는다.
