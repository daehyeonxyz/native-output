# 팀 기준으로 고치기

`standards/` 는 고쳐 쓰라고 있는 폴더입니다. 동봉된 기준은 잘 쓴 한국어의 기본값이고, 팀마다 다른 부분이 있습니다.

## 어디를 고치나

실제로 손댈 자리는 셋입니다.

### 1. `standards/dev-prose.md` 의 교정 사전

회사 용어집이 있으면 여기로 옮깁니다. 제품명과 사내 용어의 표기를 고정하는 자리입니다. 표에 한 행씩 더하면 됩니다.

```markdown
| 피해야 할 말 | 바른 말 |
|---|---|
| 우리가 쓰지 않는 말 | 우리가 쓰는 말 |
```

### 2. `standards/style.md` 의 상투어 목록

팀에서 실제로 반려된 표현을 넣고, 우리 분야에서 정상인 표현은 뺍니다.

빼는 쪽이 더 중요합니다. 예를 들어 컨설팅 보고서를 쓰는 팀이라면 "시사점" 과 "종합적으로" 는 이 장르의 정당한 어휘이므로 목록에서 빼야 합니다. 남겨 두면 매번 오탐이 납니다.

### 3. `standards/banned-words.json` 의 기계 검사 목록

훅이 Write 와 Edit 마다 대조하는 목록입니다. **이 목록은 다른 둘과 성격이 다릅니다.** 기계가 문자열로 대조하므로 오탐이 곧바로 작업을 막습니다.

```json
{ "word": "막을 말", "fix": "제안할 말" }
```

담는 기준이 하나 있습니다. **활용하지 않는 명사만 담습니다.** 동사와 형용사는 활용형이 갈려서 오탐이 납니다. 그런 항목은 `dev-prose.md` 의 표로만 관리하고 기계 검사에 넣지 않습니다.

## 고칠 때 지킬 것

**금지 항목은 실제 반려가 관측될 때만 늘립니다.** 있을 법한 표현을 미리 넣으면 오탐이 쌓이고, 오탐이 쌓이면 아무도 이 문을 열어 두지 않습니다. 기준을 죽이는 것은 느슨함이 아니라 오탐입니다.

`standards/genres.md` 의 리듬 수치는 실제 글을 측정해 얻은 값입니다. 팀 글에 안 맞는다고 느끼면 인상으로 바꾸지 말고, 팀이 잘 썼다고 합의한 글 몇 편의 문장 길이 중앙값을 실제로 세어 보고 바꿉니다.

## 배포하는 법

고친 폴더를 그대로 팀에 나눠 주면 모두가 같은 기준으로 씁니다. 각자 `~/.claude/skills/native-output/` 에 두고 `/native-output setup` 을 실행하면 됩니다.

저장소로 관리한다면 `standards/` 만 바뀌므로 변경 이력이 그대로 팀 글쓰기 기준의 이력이 됩니다.
