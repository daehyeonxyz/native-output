# 팀 기준으로 고치기

`standards/` 는 고쳐 쓰라고 있는 폴더다. 동봉된 기준은 잘 쓴 한국어의 실측 기본값이고, 팀마다 다른 부분이 있다.

## 어디를 고치나

실제로 손댈 자리는 셋이다.

### 1. `standards/dev-prose.md` 의 교정 사전

회사 용어집이 있으면 여기로 옮긴다. 제품명과 사내 용어의 표기를 고정하는 자리다. 표에 한 행씩 더하면 된다.

```markdown
| 피해야 할 말 | 바른 말 |
|---|---|
| 우리가 쓰지 않는 말 | 우리가 쓰는 말 |
```

### 2. `standards/style.md` 와 `standards/genres.md` 의 상투어 판정

팀에서 실제로 반려된 표현을 넣고, 우리 분야에서 정상인 표현은 뺀다.

빼는 쪽이 더 중요하다. 컨설팅 보고서를 쓰는 팀이면 "시사점"과 "종합적으로"는 그 장르의 정당한 어휘이므로 genres.md 의 "정상인 장르" 열에 올려야 한다. 남겨 두면 매번 오탐이 난다.

### 3. `standards/banned-words.json` 의 기계 검사 목록

Claude Code 의 훅이 Write 와 Edit 마다 대조하는 목록이다. **이 목록은 다른 둘과 성격이 다르다.** 기계가 문자열로 대조하므로 오탐이 곧바로 작업을 막는다.

```json
{ "word": "막을 말", "fix": "제안할 말" }
```

담는 기준이 하나 있다. **활용이 고정된 형태만 담는다.** 명사와 완결형 문구("살펴보겠습니다")는 되고, 어간만 잘라 넣으면("살펴보") 오탐이 난다. 활용형이 갈리는 동사와 형용사는 `dev-prose.md` 의 표로만 관리하고 기계 검사에 넣지 않는다.

## 고칠 때 지킬 것

**금지 항목은 실제 반려가 관측될 때만 늘린다.** 있을 법한 표현을 미리 넣으면 오탐이 쌓이고, 오탐이 쌓이면 아무도 이 문을 열어 두지 않는다. 기준을 죽이는 것은 느슨함이 아니라 오탐이다.

`standards/genres/` 의 리듬 수치는 잘 쓴 글을 측정해 얻은 값이다. 팀 글에 안 맞는다고 느끼면 인상으로 바꾸지 말고, 팀이 잘 썼다고 합의한 글 몇 편의 문장 길이 중앙값을 실제로 세어 보고 바꾼다.

## 배포하는 법

고친 폴더를 zip 으로 묶어 나눠 주면 모두가 같은 기준으로 쓴다. Claude 앱이면 각자 스킬로 올리고, Claude Code 면 `~/.claude/skills/native-output/` 에 두고 `/native-output setup` 을 실행한다.

저장소로 관리하면 `standards/` 만 바뀌므로 변경 이력이 그대로 팀 글쓰기 기준의 이력이 된다.
